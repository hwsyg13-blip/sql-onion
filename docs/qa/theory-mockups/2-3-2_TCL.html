TCL (Transaction Control Language)

트랜잭션 제어. COMMIT · ROLLBACK · SAVEPOINT · 자동 COMMIT 규칙

핵심 요약 정의

TCL은 트랜잭션을 제어하는 명령어들이다 (COMMIT, ROLLBACK, SAVEPOINT).
워드(Word)에서 작성 중인 내용은 메모리에만 있고, 저장 버튼이 COMMIT(영구 반영), CTRL+Z가 ROLLBACK(취소), 임시 저장 지점이 SAVEPOINT(부분 취소)에 해당한다.

DML 작업을 묶어서 영구 반영한다.

UPDATE EMP SET SAL = 4000 WHERE EMP_ID = 1;

→ COMMIT 시점에 INSERT·UPDATE가 디스크에 영구 반영되며, 락이 풀리고 다른 사용자도 변경 결과를 조회할 수 있다.

→ 행 1개 취소(박). SP2 이후의 DML만 되돌리므로 김·이는 그대로 남는다.

-- 트랜잭션 1: 정상 처리
INSERT INTO ACCOUNT VALUES (101, 'A', 10000);
INSERT INTO ACCOUNT VALUES (102, 'B', 5000);
COMMIT;     -- 둘 다 저장

-- 트랜잭션 2: 중간 오류
UPDATE ACCOUNT SET BALANCE = BALANCE - 1000 WHERE ID = 101;
SAVEPOINT BEFORE_DEPOSIT;

UPDATE ACCOUNT SET BALANCE = BALANCE + 1000 WHERE ID = 999;  -- 존재 X

-- 부분 취소 후 다른 처리
ROLLBACK TO BEFORE_DEPOSIT;
UPDATE ACCOUNT SET BALANCE = BALANCE + 1000 WHERE ID = 102;
COMMIT;

Before & After SAVEPOINT 동작

비어있는 EMP에 김·이·박을 차례로 INSERT하면서 SP1, SP2 두 지점을 찍어 둔다. 마지막에 ROLLBACK TO SP1을 걸면 어디까지 살아남는지, 그 뒤 COMMIT까지 어떻게 이어지는지를 시점별로 추적한다.

작업 시나리오

INSERT INTO EMP VALUES (1, '김');
SAVEPOINT SP1;
INSERT INTO EMP VALUES (2, '이');
SAVEPOINT SP2;
INSERT INTO EMP VALUES (3, '박');
ROLLBACK TO SP1;
COMMIT;

ROLLBACK TO SP1은 SP1 이후의 DML(이·박 INSERT)만 취소하고 그 이전 작업은 그대로 둔다. 그래서 최종 COMMIT 시점에는 김 한 행만 남는다. 트랜잭션 도중 일부만 되돌리고 싶을 때는 SAVEPOINT로 안전 지점을 미리 찍어두는 게 핵심 — 단, 전체 ROLLBACK이나 COMMIT이 일어나면 SAVEPOINT는 모두 사라진다는 점도 함께 기억해야 한다.
