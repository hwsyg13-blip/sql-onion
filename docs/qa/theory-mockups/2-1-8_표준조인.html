표준 조인 (ANSI Standard Join)

JOIN ... ON · 어느 DBMS든 통하는 ANSI/ISO 표준 문법

핵심 요약 정의

표준 조인은 ANSI/ISO에서 정의한, 모든 DBMS에서 통하는 조인 문법이다. JOIN ... ON 키워드를 사용한다. 앞 챕터의 조인 종류를 표준 문법으로 다시 정리한다.

개념 도식화 표준 조인의 종류

INNER
INNER JOIN (내부 조인)
양쪽 매칭만. INNER 키워드 생략 가능 (JOIN ... ON)
LEFT
LEFT OUTER JOIN (왼쪽 외부 조인)
왼쪽 모두 + 매칭된 오른쪽. OUTER 생략 가능
RIGHT
RIGHT OUTER JOIN (오른쪽 외부 조인)
오른쪽 모두 + 매칭된 왼쪽
FULL
FULL OUTER JOIN (전체 외부 조인)
양쪽 모두(매칭 안 되면 NULL 채움)

표준 OUTER 조인 — 벤 다이어그램

INNER
A ∩ B
LEFT
A 모두 + 매칭 B
RIGHT
B 모두 + 매칭 A
FULL OUTER
A ∪ B 모두
CROSS
CROSS JOIN (교차 조인)
조인 조건 없이 모든 조합. 결과 행수 = A × B
NATURAL
NATURAL JOIN (자연 조인)
같은 이름 컬럼으로 자동 매칭. 별칭 사용 불가
USING
USING (컬럼)
지정한 컬럼만 매칭. USING 컬럼에 테이블 별칭 불가

SQL 실전 조인 종류별 표준 문법

INNER JOIN (내부 조인) — 양쪽 매칭만

SELECT  E.NAME, D.DEPT_NAME
FROM    EMP E
        INNER JOIN DEPT D ON E.DEPT_ID = D.DEPT_ID;
        -- INNER 생략 가능: JOIN ... ON

LEFT OUTER JOIN (왼쪽 외부 조인) — 왼쪽 다, 오른쪽 매칭

SELECT  E.NAME, D.DEPT_NAME
FROM    EMP E
        LEFT OUTER JOIN DEPT D ON E.DEPT_ID = D.DEPT_ID;
        -- OUTER 생략 가능: LEFT JOIN

RIGHT OUTER JOIN (오른쪽 외부 조인) — 오른쪽 다, 왼쪽 매칭

SELECT  E.NAME, D.DEPT_NAME
FROM    EMP E
        RIGHT OUTER JOIN DEPT D ON E.DEPT_ID = D.DEPT_ID;

FULL OUTER JOIN (전체 외부 조인) — 양쪽 다

SELECT  E.NAME, D.DEPT_NAME
FROM    EMP E
        FULL OUTER JOIN DEPT D ON E.DEPT_ID = D.DEPT_ID;

CROSS JOIN (교차 조인) — 모든 조합

SELECT  *
FROM    EMP E CROSS JOIN DEPT D;

조인 조건 없음. 결과는 A행수 × B행수.

NATURAL JOIN (자연 조인) — 같은 이름 컬럼 자동 조인

SELECT  *
FROM    EMP NATURAL JOIN DEPT;     -- DEPT_ID로 자동 조인
특징설명
자동 매칭이름이 같은 컬럼으로 매칭
별칭 사용 X같은 이름 컬럼에 별칭 사용 불가
같은 이름 컬럼은 한 번만 등장중복 제거

의도치 않은 컬럼이 매칭될 수 있어 실무에서는 잘 쓰지 않는다.

USING 절 — 명시적 컬럼 매칭

SELECT  NAME, DEPT_NAME, DEPT_ID
FROM    EMP JOIN DEPT USING (DEPT_ID);

NATURAL vs USING vs ON

NATURAL
자동 매칭
이름이 같은 모든 컬럼으로 자동 조인. 별칭 불가, 의도치 않은 매칭 위험
USING
지정 컬럼만
괄호 안 지정한 컬럼만 매칭. USING 컬럼에 테이블 별칭 사용 불가 (E.DEPT_ID ✗)
ON
명시적 조건
조인 조건을 직접 지정. 다른 이름 컬럼끼리도 조인 가능, 별칭 자유
NATURAL vs USING차이
NATURAL자동(모든 같은 이름)
USING지정한 컬럼만

USING으로 조인된 컬럼은 테이블 별칭을 붙일 수 없다(예: E.DEPT_ID 불가).

ON 절 vs WHERE 절 (OUTER JOIN 핵심)

-- 잘못된 예: OUTER JOIN인데 WHERE로 필터하면 NULL 행이 빠짐
SELECT M.NAME, O.ORDER_ID
FROM   MEMBER M LEFT JOIN ORDERS O ON M.MEMBER_ID = O.MEMBER_ID
WHERE  O.AMOUNT > 1000;     -- 주문 없는 회원이 사라짐

-- 올바른 예: 조인 조건에 함께
SELECT M.NAME, O.ORDER_ID
FROM   MEMBER M LEFT JOIN ORDERS O
       ON M.MEMBER_ID = O.MEMBER_ID
       AND O.AMOUNT > 1000;

Oracle 사투리 vs ANSI 표준

같은 LEFT OUTER 조인을 두 문법으로 작성한 비교다. Oracle 전용 (+) 표기와 ANSI 표준 LEFT JOIN ... ON 결과는 동일하지만, 표준 문법은 어느 DBMS에서나 통한다.

-- Oracle 사투리: (+) 기호
SELECT E.NAME, D.DEPT_NAME
FROM   EMP E, DEPT D
WHERE  E.DEPT_ID = D.DEPT_ID(+);

-- ANSI 표준: LEFT JOIN ... ON
SELECT E.NAME, D.DEPT_NAME
FROM   EMP E LEFT JOIN DEPT D
       ON E.DEPT_ID = D.DEPT_ID;

↓ 두 쿼리의 결과 (동일)

이인사
박NULL

ANSI 표준은 결과 집합을 키워드 한 단어로 명확히 구분한다 — INNER는 매칭만, LEFT/RIGHT는 한쪽 기준 모두, FULL은 양쪽 모두, CROSS는 카티션 곱이다. "어느 쪽에 매칭이 없는 데이터까지 살릴 것인가"를 먼저 정한 다음 그에 맞는 키워드를 고르고, OUTER 조인의 추가 조건은 반드시 ON 절에 두어야 매칭 안 되는 NULL 행이 그대로 살아남는다.
