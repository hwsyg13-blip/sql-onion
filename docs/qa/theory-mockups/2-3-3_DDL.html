DDL (Data Definition Language)

객체 정의. CREATE · ALTER · DROP · TRUNCATE · RENAME · 제약조건

핵심 요약 정의

DDL은 테이블·뷰·인덱스 같은 객체를 만들고 바꾸고 지우는 명령어들이다 (CREATE, ALTER, DROP, TRUNCATE, RENAME).

개념 도식화 DDL 명령 5종

CREATE
객체 생성
테이블 / 뷰 / 인덱스 등
ALTER
구조 변경
컬럼 · 제약조건 추가/변경/삭제
DROP
객체 자체 삭제
테이블·뷰 그 자체가 사라짐
TRUNCATE
데이터만 비움
구조 유지 · 롤백 불가 · 매우 빠름
RENAME
이름 변경
테이블/객체 이름 바꾸기
자동 COMMIT
DDL 공통 특성
실행 즉시 영구 반영 · ROLLBACK 불가

CREATE — 객체 생성

예시 데이터 — 데이터베이스 스키마 (변경 전, 테이블 없음)

SCHEMA

스키마 (변경 전)

테이블 목록
(EMP 없음)
CREATE TABLE EMP (
    EMP_ID    NUMBER       PRIMARY KEY,
    NAME      VARCHAR2(50) NOT NULL,
    SAL       NUMBER       DEFAULT 0,
    DEPT_ID   VARCHAR2(10),
    HIRE_DATE DATE         DEFAULT SYSDATE,
    CONSTRAINT FK_EMP_DEPT FOREIGN KEY (DEPT_ID) REFERENCES DEPT(DEPT_ID)
);
-- Table created.

Before & After CREATE → ALTER → TRUNCATE → DROP 추적

EMP_ID(PK)·NAME(NOT NULL)·SAL(DEFAULT 0)을 가진 EMP 테이블을 만들고, 거기에 PHONE 컬럼을 더한 뒤, 같은 테이블에 TRUNCATE와 DROP을 차례로 적용해 본다. 데이터·구조·테이블 자체가 어느 명령에서 사라지는지를 비교한다.

ALTER는 컬럼을 추가해 구조를 키우고, TRUNCATE는 데이터만 비우되 컬럼 정의(EMP_ID·NAME·SAL·PHONE)는 그대로 남기며, DROP은 테이블 객체 자체를 지운다. 셋 다 DDL이라 실행 즉시 자동 COMMIT되어 ROLLBACK으로 되돌릴 수 없다는 점이 핵심이다. "데이터만 비우고 싶다 → TRUNCATE", "테이블 자체가 필요 없다 → DROP", "구조만 바꾼다 → ALTER" 식으로 의도와 명령을 정확히 매칭해야 한다.
