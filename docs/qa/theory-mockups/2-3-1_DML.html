DML (Data Manipulation Language)

데이터 입력·수정·삭제·조회 · INSERT · UPDATE · DELETE · MERGE · SELECT

핵심 요약 정의

DML은 테이블 안의 데이터를 입력·수정·삭제·조회하는 명령어들이다(INSERT, UPDATE, DELETE, MERGE, SELECT).
테이블을 노트에 비유하면 INSERT는 새 줄 적기, UPDATE는 줄 고치기, DELETE는 줄 지우기, MERGE는 있으면 고치고 없으면 적기, SELECT는 읽기다.

개념 도식화 DML의 분류

INSERT
새 행 입력
노트에 새 줄 적기 — VALUES · SELECT · INSERT ALL
UPDATE

줄 고치기 — SET · WHERE 누락 시 전 행 수정
DELETE
행 삭제 (롤백 가능)
줄 지우기 — DML이라 ROLLBACK 가능

DELETE vs TRUNCATE vs DROP

DELETE
DML · 롤백 가능
데이터 삭제, 테이블 구조 유지. 행 단위 처리라 느림. WHERE로 조건 가능
TRUNC
DDL · 롤백 불가
모든 데이터 삭제, 테이블 구조 유지. 자동 COMMIT, 빠름
DROP
DDL · 롤백 불가
테이블 자체를 삭제. 구조까지 사라짐. 매우 빠름
명령분류데이터테이블 구조롤백속도
DELETEDML삭제유지가능느림
TRUNCATEDDL모두 삭제유지불가빠름
DROPDDL삭제삭제불가매우 빠름
 
DELETE FROM EMP;       -- 데이터만, 롤백 가능
TRUNCATE TABLE EMP;    -- 데이터만, 롤백 불가
DROP TABLE EMP;        -- 테이블 자체 삭제

MERGE INTO EMP E
USING NEW_EMP N
   ON (E.EMP_ID = N.EMP_ID)
WHEN MATCHED THEN
    UPDATE SET E.SAL = N.SAL
WHEN NOT MATCHED THEN
    INSERT (EMP_ID, NAME, SAL) VALUES (N.EMP_ID, N.NAME, N.SAL);

DML과 트랜잭션

INSERT INTO EMP ...;
UPDATE EMP ...;
DELETE FROM EMP ...;
COMMIT;        -- 영구 반영
-- 또는
ROLLBACK;      -- 취소

DML은 트랜잭션의 대상이며 COMMIT 전까지 메모리에만 있다. COMMIT/ROLLBACK 같은 트랜잭션 제어 명령은 TCL에서 다룬다.

DML은 행 단위로 데이터를 바꾸지만 테이블 구조 자체는 건드리지 않는다. 위 작업들은 모두 COMMIT 전까지는 메모리에만 머물러 있어서, 잘못 친 UPDATE나 DELETE는 ROLLBACK으로 되돌릴 수 있다. 반대로 같은 "삭제"라도 TRUNCATE/DROP은 DDL이라 자동 COMMIT되며 되돌릴 수 없으니, 데이터만 비울지·구조까지 없앨지·되돌릴 여지를 둘지를 항상 의식해서 명령을 골라야 한다.
