식별자(Identifier)

인스턴스 구분 표식 = PK. 4대 조건 유·최·불·존 · 4대 분류 기준

핵심 요약정의

식별자(Identifier)란 엔터티 안의 인스턴스를 서로 구분해 주는 유일한 표식이다. 테이블의 기본키(Primary Key)가 된다.
같은 이름의 김철수가 100명 있어도 주민등록번호는 모두 다르다 — 이름은 일반 속성이지만 주민번호는 식별자(겹치지 않는 유일값)다.

개념 도식화식별자의 위치

회원(MEMBER) 테이블 — PK 가 모든 행을 유일하게 구분:

PK (주식별자)이름전화번호
PKM01김철수010-1111
PKM02이영희010-2222

같은 이름이어도 PK가 다르므로 100% 구분 가능.

PK는 자기 엔터티 안의 식별자, FK(외부식별자)는 다른 엔터티의 PK 를 참조한 식별자다 — ER로 같이 본다.

erDiagram MEMBER ||--o{ ORDERS : "주문하다" ORDERS ||--|{ ORDER_DETAIL : "상세 (식별 관계)" PRODUCT ||--o{ ORDER_DETAIL : "포함된다" MEMBER { VARCHAR2 MEMBER_ID PK VARCHAR2 EMAIL "보조식별자(UNIQUE)" VARCHAR2 NAME } ORDERS { NUMBER ORDER_ID PK VARCHAR2 MEMBER_ID FK } ORDER_DETAIL { NUMBER ORDER_ID PK "복합식별자" VARCHAR2 PROD_ID PK NUMBER QTY } PRODUCT { VARCHAR2 PROD_ID PK VARCHAR2 PROD_NAME }

-- 회원: 단일 PK
CREATE TABLE MEMBER (
    MEMBER_ID  VARCHAR2(10) PRIMARY KEY,   -- 주식별자
    EMAIL      VARCHAR2(100) UNIQUE,       -- 보조식별자
    NAME       VARCHAR2(50) NOT NULL
);

-- 주문상세: 복합 PK
CREATE TABLE ORDER_DETAIL (
    ORDER_ID   NUMBER,
    PROD_ID    VARCHAR2(10),
    QTY        NUMBER,
    CONSTRAINT PK_ORD_DTL PRIMARY KEY (ORDER_ID, PROD_ID),  -- 복합 식별자
    CONSTRAINT FK_OD_ORD  FOREIGN KEY (ORDER_ID) REFERENCES ORDERS(ORDER_ID),
    CONSTRAINT FK_OD_PROD FOREIGN KEY (PROD_ID)  REFERENCES PRODUCT(PROD_ID)
);

-- PK 위반 — 같은 회원ID 중복 입력
INSERT INTO MEMBER VALUES('M01', 'a@a.com', '김철수');
INSERT INTO MEMBER VALUES('M01', 'b@b.com', '박민수');   -- 에러!

-- NULL 위반 — 주식별자에는 NULL 불가
INSERT INTO MEMBER VALUES(NULL, 'c@c.com', '이영희');  -- 에러!

↓ 실행 결과 (DBMS 메시지)

SQL결과
INSERT … 'M01' … '김철수'1 row inserted.
INSERT … 'M01' … '박민수'ORA-00001: unique constraint violated (유일성 위반)
INSERT … NULL … '이영희'ORA-01400: cannot insert NULL into PK (존재성 위반)

PRIMARY KEY 제약은 유일성 + NOT NULL을 한꺼번에 강제한다 — 식별자 4대 조건 중 두 가지가 DBMS 차원에서 자동 보장된다.

이름은 같은 값이 얼마든지 나올 수 있으므로 유일성을 보장하지 못한다. 식별자의 4대 조건(유·최·불·존) 중 가장 먼저 깨지는 게 유일성이고, 결혼·개명 등으로 변할 수도 있어 불변성도 위태롭다. 업무 속성 중 자연스러운 유일값이 마땅치 않으면 회원ID 처럼 인조식별자를 만들어 PK 로 두는 것이 안전하다.
