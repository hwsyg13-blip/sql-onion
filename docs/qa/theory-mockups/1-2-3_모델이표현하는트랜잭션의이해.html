모델이 표현하는 트랜잭션의 이해

함께 성공하거나 함께 실패해야 할 작업 묶음. 관계의 필수성·식별성으로 모델에 새겨진다

핵심 요약 정의

트랜잭션(Transaction)이란 함께 성공하거나 함께 실패해야 하는 데이터 작업의 묶음이다. 모델은 이 묶음을 관계의 필수성과 식별성으로 표현한다.
계좌 이체에서 A에서 1만원이 빠지고 B에 1만원이 들어와야 정상. A에서만 빠지고 멈추면 돈이 사라지므로, 둘 다 성공하거나 둘 다 취소되어야 한다.

트랜잭션 상태 흐름

stateDiagram-v2 [*] --> Active : BEGIN / 첫 DML Active --> PartiallyCommitted : 마지막 SQL 성공 PartiallyCommitted --> Committed : COMMIT Committed --> [*] Active --> Failed : 오류 발생 PartiallyCommitted --> Failed : 디스크 쓰기 실패 Failed --> Aborted : ROLLBACK Aborted --> [*]

Active(활성) → 마지막 SQL까지 무사 통과하면 Partially Committed → COMMIT으로 영구 반영(Committed). 중간에 오류면 Failed → ROLLBACK으로 Aborted 종료.

모델에서 트랜잭션은 어떻게 보이는가

필수
관계의 필수성
주문상세는 반드시 주문이 있어야 함 (Mandatory). 주문 INSERT 시 주문상세도 함께 INSERT
식별
관계의 식별성
주문상세는 주문 PK 일부를 자기 PK로 가짐 — 주문 없이 존재 불가. DELETE 시 함께 처리 또는 차단
선택
선택 관계 (Optional)
고객은 주문이 없을 수 있음 — 트랜잭션으로 묶을 필요 없는 느슨한 연결

관계의 필수성

주문을 INSERT할 때 주문상세도 함께 INSERT되어야 정상 트랜잭션이다.

관계의 식별성

[주문]  ──── [주문상세]   :  식별 관계(실선), 주문 없이 주문상세 존재 불가

주문을 DELETE할 때 주문상세도 함께 DELETE되거나 막아야 한다.

트랜잭션 표현 예시

[고객]  ──○──── [주문]  ──────── [주문상세]
              선택              식별(실선)
표기의미
고객 ─○─ 주문고객은 주문이 없을 수 있음 (선택, Optional)
주문 ──── 주문상세 (실선)식별 관계 — 주문상세는 주문 PK 일부를 자기 PK로 가짐 (주문 없이 존재 불가)
주문 ─ ─ ─ 주문상세 (점선)비식별 관계 — 주문 키는 일반 FK로만 (주문상세가 독자 PK 보유)

SQL 실전 트랜잭션 묶음

INSERT/UPDATE/DELETE는 DML로 실행되고, COMMIT/ROLLBACK은 TCL로 트랜잭션을 마감한다.

Before & After 트랜잭션이 깨지면

A 계좌에서 B 계좌로 1만원 이체. 출금(A) → 입금(B) 두 작업 사이에서 시스템이 멈춘 상황과, 두 작업을 한 트랜잭션으로 묶어 ROLLBACK 한 상황의 잔고를 비교한다.

Before — 출금만 성공, 입금 실패

계좌잔고
A90,000 (10,000 빠짐)
B50,000 (그대로)

1만원이 사라진다.

After — 트랜잭션으로 묶었을 때

ROLLBACK 후

B50,000

데이터가 보존된다.

출금과 입금은 업무적으로 한 사건(이체)이지만 SQL 입장에선 별개의 UPDATE 두 개다. 묶지 않으면 중간 실패가 곧 데이터 모순(원자성 깨짐)이 된다. 모델에서 두 엔터티가 식별 관계나 필수 관계로 묶여 있다는 것은 곧 "이 INSERT/UPDATE/DELETE 들은 한 트랜잭션 안에서 함께 처리해야 한다"는 신호다. 함께 변해야 하는 데이터는 코드에서도 BEGIN ~ COMMIT으로 한 묶음이 되도록 설계해야 한다.
