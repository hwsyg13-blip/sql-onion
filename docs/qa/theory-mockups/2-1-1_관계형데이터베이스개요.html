관계형 데이터베이스 개요

테이블·행·열의 세계. SQL은 DDL/DML/DCL/TCL 4가지로 나뉜다

핵심 요약 정의

관계형 데이터베이스(RDB, Relational Database)는 데이터를 행과 열로 된 표(테이블)로 저장하고, 표들 사이의 관계로 데이터를 관리하는 시스템이다.
엑셀 한 권에 여러 시트(=테이블)가 있고 VLOOKUP의 키(=외래키)로 시트끼리 연결되는 구조를, 더 안전하고 동시에 다룰 수 있도록 만든 것이 RDB다.

SQL 실전 DDL → DML → TCL → DCL 흐름

예시 데이터 — 테이블 생성 직후 빈 상태

EMP

사원 테이블 (생성 직후 0행)

EMP_ID
NAME
SAL
(데이터 없음)
-- DDL: 테이블 생성
CREATE TABLE EMP (
    EMP_ID NUMBER PRIMARY KEY,
    NAME   VARCHAR2(50),
    SAL    NUMBER
);

-- DML: 데이터 입력/조회
INSERT INTO EMP VALUES (1, '김철수', 3000);
SELECT * FROM EMP;

-- TCL: 영구 저장
COMMIT;

-- DCL: 권한 부여
GRANT SELECT ON EMP TO USER1;

↓ 결과 (SELECT * FROM EMP;)

EMP_IDNAMESAL
1김철수3000

→ DDL로 표 만들기 → DML로 행 넣고 조회 → TCL로 영구 반영 → DCL로 권한 부여. 4가지 분류가 한 흐름에서 모두 등장한다.

Before & After 파일 시스템 vs RDB

직원 데이터(EMP_ID, NAME, SAL) 2건을 보관하고 "급여 2000 초과인 사람"을 찾는 상황. 텍스트 파일에 그대로 저장한 경우와 RDB의 EMP 테이블에 넣은 경우를 비교한다.

Before — 일반 파일에 저장

emp.txt
1, 김철수, 3000
2, 이영희, 4000

동시 수정 불가, 검색 느림, 무결성 보장 어려움.

After — RDB 사용

SELECT * FROM EMP WHERE SAL > 2000;

빠른 검색(인덱스), 동시 처리(트랜잭션), 무결성 제약이 보장된다.

BEFORE · emp.txt

단순 파일

1, 김철수, 3000 2, 이영희, 4000
동시 수정 불가
검색 시 매번 파싱
무결성 보장 어려움
→
AFTER · RDB

스키마·인덱스·트랜잭션

SELECT * FROM EMP WHERE SAL > 2000;
인덱스로 빠른 검색
트랜잭션으로 동시 처리
제약조건으로 무결성 보장

파일에는 데이터의 의미·타입·관계 정보가 없어 매번 읽어 직접 파싱해야 하고, 두 사람이 동시에 수정하면 한쪽 변경이 사라진다. RDB는 스키마(타입·제약)·인덱스·트랜잭션을 엔진이 보장하므로 데이터가 많거나 여러 사용자가 함께 쓰는 환경에서는 단순 파일이 아니라 RDB로 관리해야 한다.
