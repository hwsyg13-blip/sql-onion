관계(Relationship)

두 엔터티의 연결. 4요소 · 차수 3종 · 식별/비식별 · FK로 구현

핵심 요약정의

관계(Relationship)란 두 엔터티가 서로 어떻게 연결되어 있는지 표현한 것이다.
가족에서 '부모 ─ 자식 : 낳다/자식이다'처럼, 데이터 모델에서도 '회원 ─ 주문 : 주문하다/주문되다', '부서 ─ 사원 : 소속하다/소속되다'와 같이 양방향 동사로 표현한다.

개념 도식화관계의 4요소

회원 1명 → 주문 여러 건 (1:N 관계). 양방향 관계명을 모두 명명한다.

관계의 분류 — 식별 vs 비식별

━━ 식별 관계 (실선)
자식의 PK에 부모 식별자가 포함됨 (강한 종속)
자식이 부모 없이 존재 불가 (예: 주문 ↔ 주문상세)
┄┄ 비식별 관계 (점선)
부모 식별자가 자식의 일반 속성(FK)으로만 들어감 (약한 종속)
자식이 부모 없이도 존재 가능 (예: 부서 ↔ 사원)

설계 단계의 관계는 SQL 단계에서 조인으로 활용된다. 관계와 조인의 연결은 관계와 조인의 이해에서 자세히 본다.

-- 회원(부모) 1 : N 주문(자식)
CREATE TABLE MEMBER (
    MEMBER_ID  VARCHAR2(10) PRIMARY KEY,
    NAME       VARCHAR2(50)
);

CREATE TABLE ORDERS (
    ORDER_ID   NUMBER PRIMARY KEY,
    MEMBER_ID  VARCHAR2(10),  -- 외래키(관계의 구현)
    ORD_DATE   DATE,
    CONSTRAINT FK_ORDER_MEMBER
        FOREIGN KEY(MEMBER_ID) REFERENCES MEMBER(MEMBER_ID)
);

-- 관계는 곧 조인이 된다
SELECT M.NAME, O.ORDER_ID, O.ORD_DATE
  FROM MEMBER M
  JOIN ORDERS O ON M.MEMBER_ID = O.MEMBER_ID;

↓ 결과

김철수10022026-04-05

→ MEMBER_ID로 두 테이블이 연결되어 회원 1명의 여러 주문이 한 행씩 펼쳐진다(M01 → 1001/1002 두 행).

설계의 1:N 관계가 SQL 단계에서 ON M.MEMBER_ID = O.MEMBER_ID 한 줄로 구현된다 — 관계의 의미가 그대로 조인 조건이 된다.

Before & AfterM:N 관계의 분해

학생은 여러 과목을 듣고 한 과목에는 여러 학생이 등록한다 — 양쪽 모두 다(多)인 M:N. 이 관계를 그대로 두려는 시도와, 가운데 '수강' 교차 엔터티를 끼워 1:N 두 개로 쪼갠 형태를 비교한다.

M:N 을 그대로 두면 학생 행에 "수학, 영어, 국어" 같은 다중값 컬럼을 넣을 수밖에 없는데, 이는 1NF 위반이고 성적·수강일 같은 관계 자체의 속성도 둘 곳이 없어진다. 가운데에 수강 같은 교차 엔터티를 두면 (S01, K1) 한 줄이 한 수강 사실을 표현하므로 관계 속성도 자연스럽게 거기에 붙는다. 양쪽이 다(多)인 관계를 만나면 반사적으로 교차 엔터티를 끼워 1:N + 1:N 으로 분해하는 것이 안전하다.
