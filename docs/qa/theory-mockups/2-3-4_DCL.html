DCL (Data Control Language)

권한 통제. GRANT · REVOKE · 시스템/객체 권한 · ROLE · WITH GRANT OPTION

핵심 요약 정의

DCL은 사용자에게 권한을 주거나 회수하는 명령어들이다 (GRANT, REVOKE).
사무실 출입카드처럼 신입에게 발급(GRANT)·퇴사자 회수(REVOKE)·부서별 묶음(ROLE)으로 누가 어떤 테이블을 SELECT/INSERT/UPDATE 할 수 있는지를 통제한다.

개념 도식화 DCL 명령 2종

GRANT
권한 부여
GRANT 권한 ON 객체 TO 사용자 · ROLE 부여도 GRANT 로 함
REVOKE
권한 회수
REVOKE 권한 ON 객체 FROM 사용자 · WITH GRANT OPTION 시 연쇄 회수

권한의 종류

SYS

DB 자체에 대한 권한 — 접속, 객체 생성, 사용자 생성 등. 부여 시 옵션은 WITH ADMIN OPTION
↓
OBJ
객체 권한 Object Privilege
특정 객체(테이블/뷰 등)에 대한 권한 — SELECT/INSERT/UPDATE/DELETE/ALTER/EXECUTE/REFERENCES. 부여 시 옵션은 WITH GRANT OPTION

→ 두 권한 모두 회수. 다른 권한은 영향 없으며, 회수된 권한으로는 더 이상 해당 작업을 수행할 수 없다.

연쇄 회수

WITH GRANT OPTION으로 다른 사람에게 부여된 권한도 함께 회수된다.

사용자 관리 (참고)

CREATE USER, ALTER USER, DROP USER 자체는 DDL이지만 권한 관리와 짝을 이룬다.

-- 사용자 생성
CREATE USER USER1 IDENTIFIED BY password123;

-- 비밀번호 변경
ALTER USER USER1 IDENTIFIED BY newpass;

-- 사용자 삭제
DROP USER USER1;
DROP USER USER1 CASCADE;     -- 소유 객체까지 모두 삭제

Oracle에서 사용자 = 스키마(객체 모음). 사용자 생성 권한은 DBA가 가진다.

권한 흐름 예시

-- 관리자(DBA)로 접속
CREATE USER STAFF IDENTIFIED BY pw1234;

GRANT CREATE SESSION TO STAFF;       -- 접속 권한
GRANT SELECT ON HR.EMP TO STAFF;     -- HR 스키마 EMP 조회 권한

-- STAFF로 접속
SELECT * FROM HR.EMP;     -- 가능

-- 권한 회수
REVOKE SELECT ON HR.EMP FROM STAFF;

SELECT * FROM HR.EMP;     -- 권한 부족 에러

↓ 결과 (STAFF의 작업 가능 여부)

Before & After USER1 권한 변화 추적

방금 만들어진 USER1 계정에 권한을 한 단계씩 부여하다가 마지막에 SELECT 한 가지만 회수해 본다. 시스템 권한(CREATE SESSION)이 먼저 있어야 접속 자체가 되고, 그 위에 객체 권한(SELECT/INSERT)이 올라가는 순서를 따라간다.

시점별 권한 표

시점가능한 작업
초기접속도 불가
GRANT CREATE SESSION 후접속 가능
GRANT SELECT ON EMP 후EMP 조회 가능
GRANT INSERT ON EMP 후EMP 입력 가능
REVOKE SELECT ON EMP 후EMP 조회 불가 (INSERT는 유지)

권한은 "접속(시스템 권한) → 개별 객체 작업(객체 권한)" 순으로 쌓인다. CREATE SESSION이 없으면 SELECT 권한이 있어도 접속 자체가 안 되고, REVOKE는 해당 권한만 정확히 떼어내므로 INSERT 권한은 그대로 남는다는 점에 주의한다. WITH GRANT OPTION으로 재부여된 권한이라면 REVOKE 한 번에 연쇄적으로 회수된다는 점까지 함께 기억하면 된다.
