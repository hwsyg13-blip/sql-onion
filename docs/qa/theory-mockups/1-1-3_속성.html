속성(Attribute)

엔터티의 세부 정보 항목 = 컬럼. 3가지 분류 기준 · 도메인

핵심 요약정의

속성(Attribute)이란 엔터티가 가지는 세부 정보 항목, 곧 컬럼이다. 엔터티를 설명하는 가장 작은 단위다.
명함 한 장에서 명함 자체는 엔터티(사람), 이름·전화번호·이메일 같은 각 항목이 속성이다. 이름은 더 이상 쪼개지지 않는 최소 단위.

개념 도식화엔터티 / 인스턴스 / 속성 / 속성값

회원(MEMBER) 테이블 예시 — 각 행 = 인스턴스, 각 칸 = 속성값, 각 컬럼 = 속성.

ID (속성)이름 (속성)전화번호 (속성)
M01김철수010-1111 ← 속성값(Value)
M02이영희010-2222

엔터티 박스 안에 속성이 자리 잡는 모습을 ER로 본다.

도메인(Domain) — 속성의 값 범위

도메인은 속성이 가질 수 있는 값의 종류·범위·제약을 정의한다. 데이터 타입 + 크기 + 허용값(제약조건) 세 가지가 모두 도메인에 포함된다. 값이 비어있어도 되는지(NOT NULL 여부)도 도메인의 일부로, NULL을 허용할지는 속성마다 별도로 결정한다.

같은 도메인을 가진 속성은 여러 엔터티에 나와도 같은 의미로 다뤄야 한다(통합성).

CREATE TABLE MEMBER (
    MEMBER_ID    VARCHAR2(10),     -- 설계 속성
    NAME         VARCHAR2(50),      -- 기본 속성
    BIRTH        DATE,              -- 기본 속성
    AGE          NUMBER GENERATED ALWAYS AS  -- 파생 속성
                 (TRUNC(MONTHS_BETWEEN(SYSDATE, BIRTH)/12)) VIRTUAL
);

-- 도메인을 제약조건으로 표현 (CHECK)
CREATE TABLE SURVEY (
    RESP_ID      NUMBER PRIMARY KEY,
    GENDER       CHAR(1) CHECK(GENDER IN('M', 'F')),  -- 허용값 도메인
    AGE          NUMBER(3) CHECK(AGE BETWEEN 0 AND 150) NOT NULL
);

-- 데이터 입력 후 파생속성 조회
INSERT INTO MEMBER(MEMBER_ID, NAME, BIRTH) VALUES('M01', '김철수', DATE '1995-03-12');
INSERT INTO MEMBER(MEMBER_ID, NAME, BIRTH) VALUES('M02', '이영희', DATE '2000-08-21');

SELECT NAME, BIRTH, AGE FROM MEMBER;

↓ 결과 (오늘 기준 자동 계산)

NAMEBIRTHAGE (파생)
김철수1995-03-1231
이영희2000-08-2125

파생 속성은 BIRTH가 바뀌지 않는 한 자동 계산되므로 별도 저장·갱신이 필요 없다. 다만 조회마다 계산 부담이 있어, 자주 쓰면 성능을 고려해 실제 컬럼으로 저장하는 선택도 가능하다 — 이는 데이터 일관성과 트레이드오프된다.

한 칸에 두 값이 들어가 있으면 "휴대폰 번호만 검색"이나 "집 전화 변경" 같은 단순한 작업도 문자열 파싱부터 해야 하고, 번호가 세 개로 늘어나면 컬럼 자체를 늘려야 한다. 한 속성에는 한 값만 — 한 인스턴스가 같은 속성에 여러 값을 갖는 순간, 그건 별도 엔터티 후보다. 1NF 의 원자값 원칙도 같은 이야기다.
