정규화(Normalization)

중복 제거 · 이상현상 방지. 1NF → 2NF → 3NF → BCNF

핵심 요약정의

정규화(Normalization)란 데이터의 중복을 없애고 깔끔하게 정리하는 작업이다. 테이블을 단계적으로 쪼개서 이상현상을 막는다.
옷장 한 칸에 속옷·양말·셔츠·외투를 다 욱여넣으면 양말 찾기가 어렵고, 셔츠를 빼다가 다른 옷이 떨어진다. 칸을 나눠 종류별로 분리하는 것이 정규화다.

BCNF — 더 엄격한 3NF

3NF 까지 정규화해도 일부 비정상 종속이 남는 경우가 있다. 모든 결정자(determinant)가 후보키여야 BCNF다.

결정자란? — A → B 일 때 B 를 결정하는 A. 이 A 가 후보키 (PK 또는 UNIQUE) 가 아니면 BCNF 위반.

예시 (3NF 만족, BCNF 위반)

PK = (학생, 과목)

학생과목강사
S01수학김교수
S02수학김교수
S03영어이교수

규칙: 한 강사는 한 과목만 가르친다 → 강사 → 과목 종속 존재.
문제: '강사' 는 후보키가 아닌데 '과목' 을 결정 → BCNF 위반.

After (BCNF)

강사_과목: (강사, 과목) / 학생_강사: (학생, 강사)

단계차이
3NFPK가 아닌 컬럼이 PK에 직접 종속 (이행 종속 제거 완료)
BCNF모든 함수 종속의 결정자가 후보키 여야 함

비유하면 3NF 는 거의 깔끔, BCNF 는 완벽주의 정리다.

-- 정규화 전: 한 테이블에 모든 정보
CREATE TABLE BAD_ORDER (
    ORDER_ID NUMBER,
    PROD_ID  VARCHAR2(10),
    PROD_NAME VARCHAR2(50),  -- 상품명이 함께
    QTY      NUMBER,
    CUST_NAME VARCHAR2(50)   -- 고객명이 함께
);

-- 정규화 후: 책임에 따라 분리
CREATE TABLE PRODUCT (PROD_ID VARCHAR2(10) PRIMARY KEY, PROD_NAME VARCHAR2(50));
CREATE TABLE CUSTOMER(CUST_ID VARCHAR2(10) PRIMARY KEY, CUST_NAME VARCHAR2(50));
CREATE TABLE ORDERS  (ORDER_ID NUMBER PRIMARY KEY, CUST_ID VARCHAR2(10));
CREATE TABLE ORDER_DETAIL(ORDER_ID NUMBER, PROD_ID VARCHAR2(10), QTY NUMBER);

-- 같은 주문(주문 1: 고객 C01의 사과 2개)을 INSERT 후 SELECT
SELECT O.ORDER_ID, C.CUST_NAME, P.PROD_NAME, D.QTY
FROM   ORDERS O
       JOIN CUSTOMER     C ON O.CUST_ID  = C.CUST_ID
       JOIN ORDER_DETAIL D ON O.ORDER_ID = D.ORDER_ID
       JOIN PRODUCT      P ON D.PROD_ID  = P.PROD_ID;

↓ 결과

ORDER_IDCUST_NAMEPROD_NAMEQTY
1김철수사과2

→ 4개 테이블에 흩어진 데이터가 3-way JOIN으로 합쳐져 비정규형과 같은 모양으로 조회된다. 저장은 분산, 조회는 통합 — 정규화의 본질.

정규화로 분리한 데이터도 JOIN으로 합쳐 보면 비정규형과 같은 결과를 낸다.

After (3NF)

고객·상품·주문·주문상세 4개로 분리되어 중복이 사라진다.

같은 고객 전화번호가 주문 행마다 반복되는 것은 함수 종속이 한 테이블 안에 섞여 있기 때문이다(고객명·고객전화는 고객ID 에, 상품명·단가는 상품ID 에 종속). 종속이 다른 데이터끼리 같은 테이블을 공유하면 갱신·삭제·삽입 이상이 모두 한 자리에서 발생한다. "한 테이블엔 한 가지 의미만"이라는 원칙으로 단계적으로 쪼개면, 김철수의 전화번호는 고객 테이블 한 줄에서만 관리하면 된다.

정규화의 장단점
