# 61회 기준 기출 보완·난이도 상향 개선안 (2026-09-25)

- **작성**: 콘텐츠/QA 채팅
- **기준 회차**: 61회 — 영상 화면 캡처로 전 문항의 지문·표·SQL·보기 순서까지 대조 완료(복원율 최고). 62회는 보조 기준.
- **대상**: `scripts/authored/round-45 ~ 62.json` (18회차 × 50문항 = 900문항)

## 1. 왜 61회가 기준인가

| 항목 | 61회 | 비고 |
|---|---|---|
| 지문 대조 | 영상 화면으로 50문항 전수 확인 | 표·SQL·보기 순서까지 |
| 정답 검증 | 화면 정답 + 직접 검산 | |
| 실제 난이도 | 합격률 약 26%로 낮았던 회차 | 데이널 62회 영상 언급 |
| 문항 구성 | 표 2~4개 + SQL + 결과형 보기, NULL·수행순서 함정 다수 | 아래 §2 |

## 2. 진단 결과 (자동 측정)

### 2-1. 지문 구조
- 2과목에서 표(table) 지문이 있는 문항은 회차당 14~26개, SQL 지문은 13~29개. 61회는 표 21·SQL 29·표+SQL 19.
- **SQL/결과형 제목인데 지문(표·SQL)이 아예 없는 문항**은 1차로 92건이 잡혔지만, 보기가 구체적 결과값인 문항은 **15건**뿐이고 나머지는 정의·개념형이다. 그 15건도 함수 호출 자체가 지문인 경우가 많아 **실제 데이터 누락은 거의 없는 것으로 판단**한다 → 목록: `docs/qa/2026-09-25-missing-refs-candidates.md`. (처음 가설이었던 "45~48회 지문 누락이 많다"는 근거가 약해 A1의 우선순위를 낮췄다.)
- 해설 60자 미만 문항: 50회 23, 51회 22, 53회 24, 56회 19 … (61·62회는 0). 해설이 얇으면 오답 원인을 학습할 수 없음.

### 2-2. 출제 경향 (2과목, 회차당 평균 문항 수)
| 함정 유형 | 45~52회 | 53~59회 | 60~62회 |
|---|---|---|---|
| NULL 관련 | 11.4 | 13.1 | **15.7** |
| NOT IN / NOT EXISTS | 1.1 | 1.4 | **3.0** |
| 수행순서·별칭·ROWNUM | 1.2 | 1.7 | **3.0** |
| 서브쿼리 | 4.5 | 5.0 | **6.7** |
| PIVOT | 0.1 | 0.4 | **1.3** |
| 3개 이상 개념 결합 | 1.9 | 1.1 | **2.7** |
| 윈도우 함수 | 4.6 | 3.0 | 3.0 |
| TCL(SAVEPOINT 등) | 2.1 | 2.0 | 1.3 |

→ 최근 회차는 **NULL·서브쿼리·수행순서를 여러 개념과 결합**하는 방향으로 어려워졌다. 45~52회는 상대적으로 단일 개념 문항이 많다.

### 2-3. 정답 자동 검증 시범 (SQLite 실행)
- 시범 실행(shim 추가 전): 표+SQL 지문이 있고 실행 가능한 문항 60건 중 57건 일치, 3건 불일치 — 3건 모두 SQLite↔Oracle 방언 차이(`ROUND(x,-2)`, `||`와 NULL, 0으로 나누기)라 **실제 정답 오류는 0건**. 방언 shim 추가 후에는 §6 참고.
- 즉 검증 가능한 범위의 정답키는 신뢰할 만하다. 다만 커버리지가 낮다(보기 형식 매칭 실패 128건, Oracle 전용 구문 148건 등).

## 3. 개선 원칙

1. **정답 보존** — 기존 기출의 `correctIndex`·정답 키워드는 바꾸지 않는다(60회 난이도 작업과 동일).
2. **시험 정체성 보존** — 기출 복원 문항을 임의로 어렵게 바꾸지 않는다. **난이도 상향은 신규 문항(별도 풀)로만** 한다.
3. **근거 있는 보완만** — 원자료(영상 화면·복원 사이트)가 있는 회차는 대조로, 없는 회차는 실행 검증이 가능한 경우에만 보강한다.

## 7. 위험·한계
- 자동 검증은 Oracle 전용 구문(ROWNUM, CONNECT BY, (+), PIVOT 등)을 못 돌린다 → 그런 문항은 손 검산.
- 심화 세트는 실제 기출이 아닌 **신규 창작 문항**이다. 앱에서 기출 회차와 구분되어야 한다(풀 이름 `모의고사`, `_source: hard-mock`).
