## 규칙

1. **오래된 제보는 현재 데이터로 다시 판단한다.** 2026-10-31 R58 2과목 28번, R60 1과목 3번 제보는 5월에 들어왔지만 9월 22일 커밋(`8dffaf3` 등)으로 이미 고쳐져 있었다. 제보 시각과 `git log -- scripts/authored/round-NN.json`을 먼저 비교한다.
2. **운영 사이트 버전은 GitHub deployments API로 확인한다.** `sqldyangpa.com`은 이 환경에서 Vercel 방화벽(`x-vercel-mitigated: deny`)에 막힌다. 접속을 우회하려 하지 않는다. `gh api "repos/hwsyg13-blip/sql-onion/deployments?environment=Production"`으로 배포된 커밋을 본다.
3. **PR은 REST API로 만든다.** `gh pr create`는 GraphQL 403이 난다. `gh api repos/hwsyg13-blip/sql-onion/pulls -X POST ...`를 쓴다.
4. **npm 레지스트리 접속이 ENOTFOUND로 실패하면**, 이 환경의 npm 설정이 `registry.npmjs.org`를 프록시 예외로 두기 때문이다. 그 명령에만 `env -u NO_PROXY -u no_proxy -u npm_config_noproxy npm <cmd> --https-proxy="$HTTPS_PROXY"`로 실행한다. 전역 설정은 바꾸지 않는다. 새 세션에서는 그냥 `npm ci`가 되는 경우도 있으니 먼저 그대로 시도한다.
5. **푸시 후 원격 추적 ref를 갱신한다.** 얕은 클론이라 푸시 뒤에도 `origin/<branch>`가 옛 값으로 남을 수 있다. `git fetch origin <branch>:refs/remotes/origin/<branch>`로 맞춘다.
6. **생성 파일은 직접 고치지 않는다.** `src/data/rounds/*.ts`는 `scripts/authored/*.json`에서, 이론은 예외다 (규칙 7).
7. **이론은 `src/data/theoryHtml.ts`를 직접 고친다.** 원본 HTML/마크다운은 사용자 PC의 OneDrive에만 있어 이 환경에서 재생성할 수 없고, 9/22 커밋(`dcd87be`)도 이 파일을 직접 고쳤다. 챕터는 한 줄짜리 JSON 문자열이므로 줄 단위로 파싱해 원문이 정확히 한 번 나오는지 확인한 뒤 치환한다 (scratchpad의 `apply.cjs` 방식).
8. **`build-quiz-bank.mjs`는 PDF 없이 돌려도 안전하다.** PDF 경로가 없으면 authored/blog만 쓰고, 재생성 후 바뀐 회차 파일만 diff에 남는지 확인한다 (#197에서 `round-49.ts` 2줄만 바뀜).
9. **사용량 이벤트는 페이지 필터라 최신 값이 빈 페이지로 올 수 있다.** `list_events(kinds=["rate_limit_event"])`가 빈 결과면 `before_id=first_id`로 한 페이지 더 읽는다.
10. **화면 확인은 로컬 미리보기로 한다.** `npm run build` 후 `npx vite preview --port 4173`. 이론 화면은 `history.pushState({sqlo:true, route:'theory-detail', params:'c111'})` 후 popstate 이벤트, CBT는 `/?cbt=round-NN`. OMR 번호 버튼은 텍스트가 섞여 있어 "다음" 버튼으로 이동한다.
11. **확신이 없는 사실은 고치지 않는다.** c214 연산자 우선순위(NOT vs 비교)는 가이드 원문을 확인할 수 없어 그대로 뒀다. 웹 검색이 개인 블로그뿐이면 근거로 쓰지 않는다.
12. **봇 차단 규칙을 바꾸거나 점검할 때는 Google 크롤러 UA 전체로 시험한다.** `middleware.ts`의 `BLOCK_BOT`은 `bot` 한 글자만 있어도 막으므로, `+http://www.google.com/bot.html` 이 붙은 Google 크롤러는 `ALLOWED_BOT`에 없으면 모두 403이다. `node --experimental-strip-types`로 미들웨어 함수를 직접 호출해 확인한다.
13. **developers.google.com 은 이 환경에서 열리지 않는다.** UA 문자열 같은 사실은 Google 문서를 인용하는 공개 목록(`monperrus/crawler-user-agents`, raw.githubusercontent.com)으로 교차 확인한다.
14. **문의 시트는 Drive 커넥터 `download_file_content(exportMimeType=text/csv)` 로 전체를 읽는다.** `read_file_content` 는 앞부분만 준다. 결과가 크면 파일로 저장되므로 base64 디코드 후 csv 로 파싱한다.
15. **"2개 고르시오" 문항은 단일 선택 화면에서 정답이 둘이 된다.** 정답 번호는 유지하고 다른 하나를 반대 진술로 바꿔 단일 정답으로 만든다.
16. **보기·표가 이미지인 문항은 Read 로 이미지를 직접 열어 확인한다.** (cbt-148·sqld-0036·0359 처럼 데이터와 보기가 어긋난 문항을 이렇게 찾았다.)

17. **Vercel 은 푸시한 브랜치 자신의 `vercel.json` 을 읽는다.** #210 머지 후에도 옛 main 에서 갈라진 브랜치는 Preview 가 생겼고, main 을 합친 뒤에는 0건이었다. 작업 브랜치는 항상 최신 `origin/main` 에서 만든다 (지금까지처럼).

18. **SQL 이 보이는 화면은 연산자를 확대해서 본다.** 코딩 글꼴(D2Coding ligature) 합자로 `<>` 가 ◇, `>=` 가 ≥ 로 그려졌다 (182문항). 실제 시험지는 글자 그대로라 수험자가 연산자를 잘못 읽는다. #229 에서 `html` 에 `font-variant-ligatures: none`.

19. **같은 회차 중복은 제목+보기 정규화로 찾고, 보기만 같은 쌍은 사람이 본다.** 숫자 보기("1개/2개/3개/4개")는 우연히 겹치므로 자동 판정하지 않는다. "1과목 자리에 2과목 주제" 같은 배치 이상도 중복 신호다 (R59 1과목 5).
20. **"정답 둘" 은 해설이 스스로 털어놓는다.** "~해도 동일하게 …되지만", "명시적으로 묻는 보기는" 같은 문장이 있으면 복수 정답을 의심한다 (R52 2과목 31).

21. **묶음 머지는 "실행당 1회" 다.** 묶음을 여러 번 내면 배포 수는 줄지 않는다. 사용자 지시 작업도, 배포 한도로 미룬 작업도 다음 정기 실행 묶음에 합친다. 미룬 머지를 위해 따로 예약해 배포를 늘리지 않는다 (11-01 21시 지적).

22. **자료 형식을 바꾸면(이미지→표·SQL) 그 자료를 가리키는 문장(제목·보기·해설)도 함께 고친다.** 내용이 맞아도 "다음 그림" 이 남으면 수험자는 "그림이 없다" 고 느낀다 (11-01 1209번 제보, 64건).

23. **목록을 빼거나 더하기 전에 "번호가 밀리는가" 부터 본다.** 모의고사 번호는 필터 뒤 순번이라 중복 제거·복원이 제보 번호를 모두 어긋나게 할 뻔했다. 고정 번호표(mock-numbers.json)를 먼저 만들고 작업했다.
24. **보기를 새로 만들 때는 정답을 계산으로 정하고, 오답은 "흔한 착각" 으로 만든다** (NULL 처리, 정렬 방향, ON vs WHERE, ROLLUP vs CUBE, RANK vs DENSE_RANK). 검증할 수 없는 DBMS 동작(HH 12시 해석 등)에 기대는 문항은 같은 개념의 검증 가능한 문항으로 바꾼다.
