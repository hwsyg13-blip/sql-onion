## C. 승인 대기 — 정답 키·선택지 변경
1. **R52 2/14 (31건)**: `START WITH 매니저 IS NULL CONNECT BY (ㄱ) 사원 = (ㄴ) 매니저` 는 루트에서 아래로 내려가는 순방향이므로 `PRIOR 사원 = 매니저` → PRIOR 는 ㄱ. 현재 correctIndex=1(ㄴ)은 오답이고 해설 본문도 "PRIOR 사원"이라 쓰면서 ㄴ을 정답으로 적어 자기모순.
   수정안: `correctIndex: 0`, 해설 "루트(START WITH 매니저 IS NULL)에서 시작해 부모 행의 사원 값과 자식 행의 매니저 값이 일치하는 행을 따라 내려가는 순방향 전개이므로 PRIOR 는 사원 앞(ㄱ)에 온다."
2. **R52 2/20 (13건)**: "명령어와 분류가 올바르게 짝지어지지 않은 것은?" 에서 ② `SELECT — DQL` 도 SQLD 기준(SELECT 는 DML)으로는 틀린 짝 → 정답이 ①, ② 두 개.
   수정안: ② → `SELECT — DML`. 해설 "INSERT 는 DML 이므로 DCL 과 짝지어지지 않는다. SELECT 도 DML(데이터 조회)에 속한다." 정답 ① 유지.
3. **R52 2/48 (15건)**: `START WITH 매니저 IS NULL CONNECT BY (ㄷ) mgr = (ㄹ) empno` 는 `mgr = PRIOR empno` 가 순방향 → PRIOR 는 ㄹ. 현재 정답 ㄷ(index 2)은 역방향이라 루트 1행만 나옴. 또한 SQL 이 `SELECT 사원, 매니저` 로 표의 컬럼(empno, mgr)과 불일치.
   수정안: `correctIndex: 3`, SQL 의 SELECT 컬럼을 `empno, mgr` 로, 해설 "mgr = PRIOR empno 는 이전(부모) 행의 empno 가 현재 행의 mgr 와 같다는 뜻으로 부모→자식 순방향이다. 루트(mgr IS NULL)에서 시작하므로 PRIOR 는 ㄹ(empno 앞)에 온다."
4. **R59 2/47 (23건)**: M=MAX(VAL) OVER() → 100 전 행, S=SUM(VAL) OVER(ORDER BY ID) → 100~600 누적, F=FIRST_VALUE(...) → 100 전 행. 그런데 선택지 어디에도 이 조합이 없음(현재 정답 ④ "M=S=F=100"은 S 가 틀림).
   수정안: 선택지 ① → "M = 100 (모든 행), S = 누적 (100, 200, ..., 600), F = 100 (모든 행)", `correctIndex: 0`, 해설 재작성.
