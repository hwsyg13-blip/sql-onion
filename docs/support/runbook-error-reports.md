# CS 운영 — 사용자 오류 제보 처리 런북

**목적**: 시트로 들어온 오류 제보를 빠르게 트리아지하고 진짜 수정이 필요한 건만 골라내 PO·개발팀에 라우팅한다.

**입력**: [SQLD양파 CS 시트](https://docs.google.com/spreadsheets/d/1ZetajcAO8lDHTbYF0EwfKoytJnDjI-SAqk8510XOIDg/edit)
- 컬럼: `시각 / 회차 / 과목 / 문항번호 / 제보 내용 / 문제 제목 / UA`

**출력**: 제보별 분류 + 수정 제안 또는 응대 초안

---

## 워크플로우

```
1. 시트 새 행 → CS 트리아지
   ↓
2. node scripts/cs-triage.mjs 로 자동 분석
   ↓
3. 분류:
   ├─ LIKELY_VALID_BUG (P0/P1)  → 4. PO 검토 → 5. 수정 → 6. 응대
   ├─ NEEDS_HUMAN_REVIEW (P2)   → 4'. SQLD 강사 검토 → 분기
   └─ WORKING_AS_DESIGNED (P3)  → 7. 응대 초안으로 종결
```

---

## 1단계: 시트에서 행 가져오기

CS 가 시트를 보고 새로 들어온 행을 확인. 핵심 정보 추출:

```
회차: 제58회
과목: 1과목
문항번호: 3 (※ 사용자가 잘못 적었을 수 있음 — 문제 제목으로도 검증)
제보 내용: 선택지 1,3번이 동일한 내용이고 2번 선택지의 주어가 없음
문제 제목: 아래 학생·수강 ERD에 대한 설명 중 옳지 않은 것은?
```

**주의**: 사용자 입력 문항번호는 종종 부정확. 가능하면 **문제 제목으로 검증**하라.

---

## 2단계: 자동 분석 도구 실행

### 회차/번호로 조회

```bash
node scripts/cs-triage.mjs --round 58 --subject 1 --number 3 --report "선택지 1,3번이 동일한 내용이고 2번 선택지의 주어가 없음"
```

만약 **QUESTION_NOT_FOUND** 가 나오면 사용자가 번호를 잘못 적은 것. 제목으로 재검색:

### 제목으로 검색

```bash
node scripts/cs-triage.mjs --title "학생·수강 ERD" --report "..."
```

→ 결과: 실제 매칭 문항이 R58 1과목 Q9 였음을 확인.

올바른 회차/번호로 재실행:

```bash
node scripts/cs-triage.mjs --round 58 --subject 1 --number 9 --report "..."
```

## 3단계: 출력 해석

도구는 다음 분류 중 하나로 판정:

### LIKELY_VALID_BUG (P0/P1)

자동 분석에서 HIGH 시그널 발견:
- `EXPLANATION_MISMATCHES_ANSWER` — 해설이 다른 옵션을 설명함 (정답 키 의심)
- `DUPLICATE_OPTIONS` — 옵션 둘 이상 의미적으로 동일 (변별력 없음)
- `RAW_MARKDOWN` 등 콘텐츠 결함

→ **PO 또는 SQLD 강사 검토 필수**. 강사 비용이 부담이면 PO 자체 판단으로도 진행 가능하나, 정답 키 변경은 **재발 방지를 위해 명확한 SQL 표준 근거 명시**.

### NEEDS_HUMAN_REVIEW (P2)

MEDIUM 시그널만 있음:
- `NO_EXPLANATION` — 해설 부재로 정답 검증 어려움
- `AUTHOR_UNCERTAIN` — "원본 기출 정답 보존" 메모

→ **SQLD 강사 검토 권장**. 즉답 회피, *"확인 후 안내드리겠습니다"* 응대.

### WORKING_AS_DESIGNED (P3)

자동 분석에서 명백한 결함 발견 안됨.

→ 응대 초안 사용해 종결. 단, 제보자가 도메인 지식이 깊어 보이면 P2 로 격상 검토.

## 4단계 (LIKELY_VALID_BUG): 검토 및 수정

### 4-1. 검토 의뢰

PO 또는 강사에게 다음 형식으로 전달:

```
[검토 요청] R58 1과목 Q9

문제: 아래 학생·수강 ERD에 대한 설명 중 옳지 않은 것은?
현재 정답: 옵션 2 (3번) "동일한 수강번호를 가질 수 없다."

자동 분석 결과:
- 해설("수강 안한 학생도 존재 가능...")이 옵션 1(2번) "학생 테이블에 있으면..." 을 더 잘 설명
- 옵션 1·3이 의미적 중복 (PK uniqueness 진술 두 번)
- 옵션 1(2번)에 주어 누락 ("학생 테이블에 (있는 것이) 수강에...")

사용자 제보:
"선택지 1,3번이 동일한 내용이고 2번 선택지의 주어가 없음"

추천 수정:
- 정답 키: 2 → 1 (해설과 일관)
- 옵션 1번: "수강번호는 중복되지 않는다." (유지)
- 옵션 2번 주어 보강: "학생 테이블에 있으면 ..." → "학생 테이블에 등록된 학생은 반드시 수강목록에 존재해야 한다."
- 옵션 3번 변별: "동일한 수강번호를 가질 수 없다." → "수강 테이블의 학생ID는 학생 테이블을 참조하는 외래키이다." (또는 다른 변별 진술)

검토 부탁드립니다.
```

### 4-2. 수정 적용

승인 후 두 파일 모두 수정:

**A. `scripts/authored/round-NN.json`** (소스):
```json
{
  "subject": "1과목",
  "number": 9,
  "title": "...",
  "options": [
    "수강번호는 중복되지 않는다.",
    "학생 테이블에 등록된 학생은 반드시 수강목록에 존재해야 한다.",
    "수강 테이블의 학생ID는 학생 테이블을 참조하는 외래키이다.",
    "하나의 학생은 여러 개의 수강 이력을 가질 수 있다."
  ],
  "correctIndex": 1,
  "explanation": "수강을 하지 않은 학생도 존재할 수 있으므로 학생 존재만으로 수강 이력이 강제되지는 않는다. 따라서 옵션 2가 옳지 않다."
}
```

**B. `src/data/rounds/round-NN.ts`** (빌드 결과 — 같이 수정):
```bash
node scripts/build-quiz-bank.mjs   # 또는 직접 .ts 파일 동기화
```

### 4-3. 검증 자동화 다시 돌리기

```bash
node scripts/validate-rounds.mjs --round 58
```

ERROR 0건 확인. 그 다음 수동 검수: 제보 도구 다시 실행해서 HIGH 시그널이 사라졌는지 확인.

## 5단계: 제보자 응대

### LIKELY_VALID_BUG 수정 완료 시 응대 초안

```
안녕하세요, 양파팀입니다 🧅

제보해주신 R58 1과목 9번 문항(학생·수강 ERD 문제)에 대해 자세히 검토했습니다.

말씀하신 대로:
1. 1번과 3번 선택지가 사실상 같은 의미였고
2. 2번 선택지의 주어가 빠져 있었으며
3. 추가로 정답 표기 자체에도 오류가 있었습니다.

세 가지 모두 수정하여 [내일/이번 주 내] 반영될 예정입니다.

날카로운 지적 정말 감사드립니다. 덕분에 더 정확한 학습 자료를 만들 수 있어요.
공부 화이팅 응원합니다! 💪
```

### WORKING_AS_DESIGNED 응대 초안

```
안녕하세요, 양파팀입니다 🧅

제보해주신 R{NN} {과목} {번호}번 문항을 검토한 결과, 해당 문항은 SQLD 표준 출제 패턴을 따른 것으로 확인되어 정답·옵션·해설에 수정이 필요하지 않은 것으로 판단됩니다.

[옵션이 헷갈리셨다면 — 추가 설명: ...]

다만 학습 중 혼란이 있으셨다면 죄송합니다. 같은 유형의 다른 회차 문항도 함께 풀어보시면 패턴이 보이실 거예요.

추가 의문이 있으시면 회신 부탁드립니다 🙏
```

## 6단계: 통계 정리 (주간 리포트)

매주 월요일 `docs/support/weekly/YYYY-WW.md` 에 다음 통계 추가:

- 신규 제보 N건
- 분류별 비율: VALID_BUG / WAD / NEEDS_REVIEW
- 평균 1차 응답 시간
- 최다 제보 문항 (있으면 이슈)
- PO 에 에스컬레이션 한 항목 정리

## 부록: 자주 보는 자동 분석 시그널

| 시그널 | 의미 | 권장 액션 |
|---|---|---|
| `EXPLANATION_MISMATCHES_ANSWER` | 해설이 다른 옵션 설명 | **정답 키 재검토 필수** |
| `DUPLICATE_OPTIONS` (sim ≥ 0.5) | 옵션 의미 중복 | 옵션 변별 강화 |
| `NO_EXPLANATION` | 해설 비어 있음 | 강사에게 해설 작성 요청 |
| `AUTHOR_UNCERTAIN` | "원본 정답 보존" 메모 | 강사 검수 P0 |
| `RAW_MARKDOWN` | 데이터에 `**` 잔존 | 데이터 클리닝 |
| `NTILE_OUT_OF_RANGE` | NTILE(N)에 N+범위 외 답 | 답 자체 오류 (P0) |
| `TUPLE_IN_OR_ANSWER` | 튜플 IN인데 OR 형식 답 | 정답 키 OR→AND 검토 |

## 부록: 자동 분석으로 못 잡는 케이스

도구 한계상 **사람만 잡을 수 있는** 결함:
- 의미적 동의어 (n-gram 유사도가 약함) — 예: "수강번호 중복 X" vs "동일 수강번호 X"
- 한국어 문법·주어 누락 (자연어 분석 X)
- SQL 의미 오류 (RANGE 계산, NULL 처리, 계층형 동작)
- 출제 의도와 실제 정답의 미묘한 차이

→ 이런 케이스는 사용자 제보가 가장 중요한 1차 발견 채널. CS는 사용자 제보를 **가볍게 보지 말 것**.
